# 실제 의류 패턴의 등거리 조립 — ARAP + 굽힘

GarmentCodeData 한 벌(`rand_00YONAPXZE`)의 **평면 패널 18장 + 봉제 54개만** 주고,
외력 0에서 등거리 조립을 푼다. 중력 없음, 몸 없음, 충돌 없음.

```
python gcd_io.py                        # 입력 파이프라인 점검
python run_garment.py --fast            # 빠른 확인 (약 3분)
python run_garment.py --seed 1          # 본 실행 1회
python run_garment.py --seed 1 --inflate 1.5
python measure_all.py                   # 4절 (a)~(f) 전부
```

**드레이프(`_sim.ply`의 3D 좌표)는 솔버 입력이 아니다.** 4(e) 사후 비교에만 쓴다.

## 0. 선결 사항 (지시서 §1)

### §1.2 `E_bend` 부호 확인 — **부호 버그 없음**

| | r=0.9 | r=1.0 | r=1.1 | r=2.0 |
|---|---|---|---|---|
| **A. 같은 rest** (지시서 절차 그대로) | 60.571 | 74.779 | **90.483** | — |
| **B. 각 r에 등거리인 rest** (대조군) | 83.088 | 74.779 | **67.981** | 37.390 |

A는 `E(1.1)/E(0.9) = 1.49383`, `(1.1/0.9)² = 1.49383` — **정확히 일치**한다.
`E_bend`는 `p`에 대한 고정 2차형식이고 세 원통은 x,y 성분만 `r`배 다르므로 `E ∝ r²`가 나오는 게
당연하다. **이 세 배열 중 rest와 등거리인 것은 r=1.0뿐**이고 나머지는 원주 방향으로 `σ₁ = r`만큼
늘어난 상태다.

B는 각 반지름에 등거리인 rest를 준 대조군이다. 여기서 `E_bend`는 `r`에 대해 **감소**하고
`3·∫κ²dA = 3·2πH/r`와 비율 **0.99179로 일정하게** 일치한다. 모델이 유효한 영역(등거리)에서
조립과 부호가 정확하다.

⇒ 토이의 `r = R_poly/(1+3λ_b)` 관계식은 성립하지만 **해석을 고쳐야 한다.** `λ_b`가 원통을 줄이는
것은 "굽힘이 작은 반지름을 선호"해서가 아니라, 2차 굽힘 모델이 **rest 계량의 라플라시안**을 재기
때문에 등거리에서 벗어난 상태의 신축을 굽힘으로 오인해서다(참값 대비 `r³`배 과벌점).
옷 실행은 `λ_b`가 작고 해가 거의 등거리라 이 아티팩트는 무시할 수준이다.

### §1.1 봉제선 힌지 포함 — 일반 규칙으로 구현

`assembly.build_hinges()`는 **용접 위상의 모든 내부 엣지**에 대해, 두 삼각형을 각자의 rest 변
길이로 **한 평면에 펼쳐서**(unfold) 스텐실을 만든다. 봉제선이든 아니든 같은 코드 경로다.
공유 엣지 길이가 양쪽에서 다르면(개더) 평균을 쓴다.

```
x0 = (0,0),  x1 = (L,0),  L = (L_A + L_B)/2
x2 = ( (L²+p²−q²)/2L ,  +√(p²−X²) )      p,q = 삼각형 A의 나머지 두 변
x3 = ( (L²+p'²−q'²)/2L, −√(p'²−X'²) )    p',q' = 삼각형 B의 나머지 두 변
```

검증: 85,441개 힌지 전부에서 `max|ΣK| = 8.9e-16`, `max|ΣK·x| = 8.9e-16` — 스텐실이 rest의
아핀 종속 관계를 정확히 만족한다.

## 1. 입력 파이프라인

`_sim.ply`에서 가져오는 것과 **가져오지 않는 것**:

| | 용도 |
|---|---|
| 면 목록 | 삼각형 연결관계(위상)만 |
| UV `(s,t)` | → 평면 rest 재질 좌표 |
| 동일 3D 좌표로 용접 | 봉제 정점 **대응관계**만 |
| ~~3D 좌표(드레이프)~~ | **솔버 입력 아님.** 4(e) 사후 비교 전용 |

정점 **29,784** / 용접 **28,817** / 면 **57,130** / 봉제쌍 **967** / 힌지 **85,441** — 지시서 §2와 일치.

### UV → 재질 좌표 복원

`pi/gcd.py`는 이 리포지토리에 없어서 직접 유도했다. UV는 축마다 독립적으로 정규화돼 있으므로
재질 좌표는 `(s·Kx, t·Ky)`이고 `Kx ≠ Ky`다. 보정 기준은 `_orig_lens.pickle` — 시뮬레이터가
쓴 **rest 엣지 길이**이고, 드레이프가 그 계량 위에서 계산됐으므로 올바른 기준이다.
제곱 길이에 대한 선형 최소제곱으로 푼다.

```
Kx = 397.0267 cm,  Ky = 228.2157 cm      (7,555개 엣지로 적합)
rest 엣지 길이 오차:  중앙값 0.346%,  p90 0.736%
```

지시서가 언급한 1.26%보다 좋다. **등방 단일 배율은 중앙값 17.4% 오차** — 비등방이 필수다.

### 패널 귀속

raw 메시에서 각 패널은 **연결 성분 하나**다(봉제 정점이 패널마다 복제돼 있어 패널끼리 연결이
없다). 성분 18개를 세그멘테이션 라벨의 최빈값으로 패널에 매핑했고, **면이 두 패널에 걸치는
경우가 0건**임을 assert한다. 라벨 상속 스윕이 필요 없다.

### ⚠ 뒷면 패널의 거울상 파라미터화

`shape_gradients`가 잡아낸 것: **뒷면 패널 면의 100%가 rest 넓이 음수, 앞면은 0%**다.

| 앞면 패널 | 음수 비율 | 뒷면 패널 | 음수 비율 |
|---|---|---|---|
| `*_ftorso`, `*_sleeve_f`, `*_cuff_f`, `skirt_front`, `wb_front`, `*_hood` | 0% | `*_btorso`, `*_sleeve_b`, `*_cuff_b`, `skirt_back`, `wb_back` | 100% |

부호 있는 넓이를 그대로 쓰면 메시 절반에 **음수 가중치**가 걸려 강성행렬이 부정부호가 되고
해가 통째로 무의미해진다. `|A_t|`를 쓰는 것이 임시방편이 아니라 정확한 처리다 — rest를
거울상으로 바꾸면 `F → F·M`(반사)이고 **특이값이 불변**이며, `R`이 도는 슈티펠 다양체
`V₂(R³)`는 두 방향을 모두 포함하므로 `‖F−R‖²`도 불변이다.

## 2. 봉제선의 rest 길이 — 패턴은 맞춰져 있다

용접된 봉제 엣지 845개에 대해, 양쪽 패널에서 본 rest 길이의 비를 쟀다.

| | 엣지 수 | 길이비 |
|---|---|---|
| **비개더 봉제선** | 670 (79.3%) | **p50 1.00000**, p99 1.0255, max 1.0257 |
| 설계 개더 (스커트 → 허리밴드) | ~89 | 1.077 |
| 설계 러플 (소매 → 커프) | 76 | **1.8438** |

**비개더 봉제선의 길이비는 정확히 1.00000이다** — 패턴은 등거리 조립이 되도록 설계돼 있다.
불일치는 설계가 명시한 개더뿐이고, 설계 파일이 그것을 확인해준다:

```
sleeve.cuff.top_ruffle:  v: 1.8442596005234544      (메시에서 측정: 1.8438)
```

유효숫자 4자리 일치다. 개더 봉제선에서는 용접이 준 대응이 **1:1**이라 긴 쪽이 길이비의 역수만큼
압축될 수밖에 없다(`|σ−1| ≈ 1 − 1/1.844 = 0.46`). 따라서 `max|σ−1|`은 **개더 접촉 면
(전체의 1.24%)을 분리해서** 보고한다. 솔버의 문제가 아니라 설계의 성질이다.

## 3. 솔버

토이와 같은 에너지, 두 군데만 일반화했다.

* **rest가 정점이 아니라 삼각형마다** 있다. 봉제 정점은 인접 패널마다 복제되고 패널마다 다른
  평면 위치를 주므로 정점당 rest가 유일하지 않다. 삼각형은 항상 한 패널에 속하므로 항상 있다.
* **힌지 스텐실을 unfold로** 만든다(§0의 §1.1).

`w_s` 연속법은 **Woodbury**로 흡수한다 — `DᵀD`의 랭크가 봉제쌍 수(967)뿐이라, `L0` 한 번
인수분해에 `w_s` 전체 스케줄이 붙는다. 반복당 재분해 0회. `λ_b`는 `L0` 안에 있으므로 사다리
한 단당 인수분해 1회, 실행 전체에서 8회다.

`λ_b` 사다리는 **토이와 동일**: `1e-1 → 1e-2 → … → 1e-8`. 케이스마다 다른 값을 쓰지 않는다.

### 실측 비용

| 항목 | 시간 |
|---|---|
| 로드 + 힌지 85,441개 구성 | 4.3초 |
| 인수분해 1회 (29,784² 희소, nnz 374,422) + Woodbury `Y` (230 MB) | 8.0초 |
| **반복 1회** (희소 solve 3열 + 57,130개 3×2 SVD) | **0.28초** |
| 본 실행 1회 (사다리 8단, ~3,480 반복) | **약 26분** |
| 빠른 실행 (사다리 4단, 680 반복) | **3.1분** |

병목은 단일 연산이 아니라 **반복 횟수**다.

## 5. 파일

```
gcd_io.py       GarmentCodeData 로드, UV→재질 복원, 용접/봉제쌍, 패널 귀속, 배치
assembly.py     삼각형별 rest ARAP, unfold 힌지 굽힘, Woodbury 전역 풀이, λ_b 어닐링
analyze.py      Procrustes, 각 결손, 봉제 길이비, 삼각형-삼각형 교차
run_garment.py  한 번의 조립 실행 -> result/assembly_<tag>.{ply,npy,json}
measure_all.py  4절 (a)~(f)
plyio.py        패널 색 입힌 ASCII PLY + 렌더러
result/         조립 결과, 측정값
tmp/            초기값·중간 확인용 렌더
```

PLY는 ASCII이고 정점마다 패널 색과 `panel` 속성을 담는다.
